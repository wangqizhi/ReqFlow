# ReqFlow 2.12.2

## 主要更新

- 关联 Server Agent 后，桌面端及 CLI 的 flow 操作直接在远程服务器执行，采用服务端业务规则和 SQLite 事务；本地只更新服务端已确认结果的备份。并发版本不一致时拒绝覆盖，远程不可用时禁止在本地偷偷修改关联 flow。
- 移除「立即推送」和「从服务端拉取」，提供「中断远程同步」，中断后可使用最后一次确认的本地备份继续编辑。重新关联时，已有远程 flow 优先于本地快照。
- 服务端配置、项目、需求与步骤改用 SQLite 保存。首次启动自动迁移旧 JSON 项目和步骤，迁移后不再用旧 JSON 覆盖数据库；升级旧关联时，可从本地备份补回旧快照缺失的图片内容。
- 修复 SSH 安装忽略自定义数据目录的问题，支持绝对路径与 `~/` 路径，安装完成显示实际数据目录。程序与部署配置仍位于 SSH 用户的 `~/reqflow-server`。
- 新增远程卸载：先检查实际卸载范围，默认保留数据，也可明确选择永久清理数据目录。停止进程并清除 systemd / crontab 自启；清理前核对部署标记，拒绝根目录、主目录、程序目录及符号链接目录。
- 修复未保存草稿确认指纹时提示「服务端配置不存在」：先保存被测试的配置及令牌，再使用返回的 ID 信任并连接；保存失败保留草稿，重试不重复新增。
- 信任时核对当前证书与用户确认的指纹一致；不匹配时拒绝信任，并保留原信任记录。

## 验证

- 覆盖远程业务操作、CLI 路由、并发冲突、断网阻止本地写入、中断关联恢复本地编辑、同服务器项目间移动、归档、图片读写和旧数据迁移。
- 覆盖自定义目录解析、SQLite 配置、卸载清理边界与符号链接保护、草稿保存后信任及失败重试。

## 升级

- 桌面端和远程 Server Agent 需要一起更新，才能使用新的远程 flow 接口。
- 同一数据目录内会自动迁移旧 JSON 数据，原 JSON 保留为迁移备份。
- 更换数据目录不会自动搬迁已有数据；有数据的部署请先备份并搬迁，再切换目录。
- 跨本地与远程或跨不同服务器移动需求前，请先中断远程同步。
