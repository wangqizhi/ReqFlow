# ReqFlow 2.8.4

## 主要更新

- REQ-173：在「插件/MOD/AGENT → 实验室」增加默认关闭的 Terminal 开关。开启后，发布时在主区底部显示 xterm 日志面板，增量读取脚本的标准输出与错误输出，无需等脚本结束；支持 ANSI、滚动查看、收起与重新打开。每个项目保留独立的本次发布会话，切换项目不会中止发布。
- 发布前的 Git 操作在面板标题中显示当前步骤，发布结束显示成功或失败。关闭 Terminal 时继续使用原有完成弹窗。Terminal 当前仅查看输出，尚不提供交互式 Shell 或 PTY。
- 实时输出独立于持久化发布日志开关，内存缓存保留最近 200 KiB，并限制保留会话数量；Python 发布脚本使用无缓冲输出。
- REQ-172：「我的项目」分组（含标题）最多占侧栏高度的一半，超过后项目列表内部滚动；滚动条使用侧栏的深灰配色，保留文件夹、项目管理和新建入口。

## 交付说明

本次为小功能与样式调整，影响文件少于 20 个，版本升级至 2.8.4。生成 Windows x64 安装包、便携版及 SHA256 校验文件，不自动安装。

## 验证记录

- `npm run typecheck`、`npm run smoke`（Go 测试与 vet）、`npm run build`、`npm run dist` 和 `npm run package-check` 均通过。打包校验包含实际 EXE/便携版的版本、SQLite 与发布 dry-run，不上传或安装。
- `REQFLOW_UI_NOTIFICATION=0 npm run check:mygo:ui` 通过：使用真实 WebView2 与隔离数据副本，覆盖发布结束前的输出、标准错误输出、收起与恢复、项目切换、实验室开关、关闭弹窗后保留结果，以及 1440×900 / 1440×720 的终端与长项目列表布局。
- 默认界面检查中的原生通知检查未通过：Windows 返回 `无法显示 Windows 通知: Unspecified error`。上面的界面复测显式跳过该原生通知检查，通知功能未在本轮修复；其余检查均通过。
