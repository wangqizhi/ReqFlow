# ReqFlow 1.4.0

本轮 6 条已领取需求：完成 REQ-044（验证退回修订）、046、048、049、050；REQ-047 已分析，等待用户确认导航方案，未删除批次历史 Tab，不回写完成。超过 3 条小版本升级：1.3.2 → 1.4.0。

## 改动

- REQ-044：连接测试在独立临时目录使用只读 `ls-remote --symref ... HEAD`，不克隆、不检出分支、不写入项目目录，隔离数据目录的局部 Git 配置影响。创建目录时若填了仓库则尝试拉取，失败保留目录并提示调整地址/分支/认证配置。创建项目时拉取失败继续保留项目并引导打开仓库设置。全局设置删除项目仓库页，入口迁到浏览目录顶部的仓库设置图标，打开独立浮层，可保存、测试或应用 origin。
- REQ-046：主 Tab「待执行 / 待开发」改为「需求池 / 排期表」，机器状态字段与生命周期不变，相关帮助同步。
- REQ-048：设置按钮上方新增带图标的插件/MOD 入口。界面直接渲染 `docs/mod-protocol.md` 单一源文件，涵盖项目选择、有效需求筛选、认领、待人工审核、版本/幂等/错误/权限约定；明确区分现有 CLI 与未来协议，未实现插件加载器或新的认领 API。
- REQ-049：所有自定义对话浮层可按住顶部区域拖动（新建/编辑/确认、设置、帮助、AI 需求、MOD、文件浏览、提交文案、仓库设置等）。控件不会触发拖动，拖动受视口边界约束，窗口缩小时保持可访问。系统原生对话框由操作系统提供拖动。
- REQ-050：侧栏改为「协作项目」，显示「开发中」和未来同步协作说明，不实现同步服务。

## REQ-047 待确认

分析在 `docs/batch-history-analysis.md`。批次记录排期快照、Prompt、hash 与提交/取消状态，是 Agent 核对过期执行的基础，不能直接删底层数据。建议将独立 Tab 移入排期表的「历史排期」次级入口，保留全部数据与 CLI。等待用户选择保留、移入排期表或仅隐藏；本轮尚未更改该入口。
