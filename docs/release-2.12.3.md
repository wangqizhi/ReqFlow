# ReqFlow 2.12.3

## 主要更新

- 在「设置 → Server Agent」每张服务端卡片的测试连接、编辑和重置信任旁新增「更新 Server」，通过原部署的免密 SSH 用户上传桌面安装包自带的 Linux 服务端程序。
- 更新前识别远程架构，校验本地服务端文件的版本、大小与 SHA256，并核对原部署访问令牌，避免更新到错误的 SSH 用户或服务器。
- 更新保留原访问令牌、证书、监听地址、端口和数据目录，不重新安装或重置项目关联；兼容旧 JSON 部署配置并转换为等价的 SQLite 配置。
- 先备份原程序及启动配置，再原子替换并重启。更新后检查版本与 `flow-v2` 接口、认证及证书指纹；失败时尝试恢复原程序、配置与开机启动项，并显示明确结果。
- 更新成功后记住 SSH 目标，并在服务端卡片显示已验证的服务端版本；手动断开的连接不会因更新而自动恢复。

## 验证

- 覆盖旧 JSON / SQLite 部署配置的保留、错误部署识别、包内版本与文件完整性校验、SSH 目标保存。
- 覆盖更新后版本、接口、访问令牌与证书指纹检查，以及恢复脚本的数据目录保护。

## 使用

- 先升级桌面端，再点击目标卡片的「更新 Server」，填写原部署使用的 SSH 用户和端口，例如 `root@nas.lan` 或 `user@nas.lan:2222`。
- 自签证书部署请先测试连接并确认原服务端指纹。更新期间服务会短暂重启，完成后可继续使用远程 flow 操作。
