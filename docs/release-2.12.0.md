# ReqFlow 2.12.0

## 主要更新

### 安装包修复（2026-10-26）

- 修复打包参数名不一致导致 Linux amd64 / arm64 服务端文件未进入安装包的问题，解决 SSH 自动安装提示“安装包内缺少 reqflow-server-linux-amd64”。本版本安装包已重新生成。
- 打包和发布前强制检查两个架构服务端文件的大小与 SHA256，并通过实际安装、卸载测试验证文件分发，防止缺少服务端文件的安装包再次发布。

### 远程同步服务端（Server Agent）

- 新增可独立部署的 ReqFlow 同步服务端，与桌面端同一 Go 代码库、独立入口命令：安装目录下的 `ReqFlow.exe server ...`，安装包同时附带 Linux amd64 / arm64 的 `reqflow-server` 二进制，可直接部署到 NAS、云主机或常开设备。
- 服务端用单一命令启动：`reqflow-server server run --port 8787 --data-dir <目录> --config <文件>`，启动日志打印实际监听地址、访问令牌与证书指纹；也支持 `--host / --token / --cert / --key` 覆盖配置。
- 支持注册为系统服务：Windows 上 `server install` 注册为真正的 Windows 服务（SCM 托管、开机自动拉起，无管理员权限时回退计划任务）；Linux 上生成 systemd 用户单元并尝试启用。另有 `server uninstall / start / stop / status / token [--rotate]` 管理命令。
- 单用户访问令牌模型：所有同步接口要求 `Authorization: Bearer <令牌>`，未携带或无效令牌返回 HTTP 401 与 `UNAUTHORIZED` 错误码；令牌可在首次启动自动生成，也可用 `--token` 指定或 `server token --rotate` 轮换。
- 服务端数据目录独立于桌面客户端（`projects/`、`certs/`），误指向客户端数据目录时会拒绝启动。

### 客户端信任与连接

- 客户端支持两种证书模式：「自签证书 + 首次连接指纹确认」与「受信任 CA 证书」。首次连接展示服务端证书 SHA-256 指纹，用户确认后才建立信任；已信任服务端的指纹变化时阻断连接，提示「证书已变更」并提供重置信任入口，避免中间人攻击。
- 访问令牌与证书指纹经 Windows DPAPI 加密保存在本地，不进入工作区导出、Git 备份或远程同步。
- 连接测试分别报告 DNS / 端口不可达、证书不匹配、令牌无效三类失败原因。

### Server Agent 管理界面

- 「设置」新增 Server Agent 分类：新增与编辑远程服务端（名称、地址、端口、证书模式、访问令牌、开机自动连接），支持保存多套配置。
- 列表展示每套服务端的连接状态（已连接 / 断开 / 证书异常 / 待确认信任）、最近连接与最近同步时间，失败时显示具体原因；支持手动断开与重连，断开后本地功能不受影响。
- 提供「SSH 自动安装」：对已配置免密登录的 Linux 服务器，自动上传对应架构的 reqflow-server、生成配置与令牌，并通过 systemd / crontab 设置开机自启，完成后自动生成客户端配置草稿。

### 项目远程同步

- 项目设置新增「远程同步」页签：项目可关联某个 Server Agent。关联后所有 flow 数据（需求、批次与全部步骤）在每次变更时自动推送服务端，本地始终保留一份；发布等操作仍在本地进行，服务端只保存 flow 数据。
- 支持手动「立即推送」与「从服务端拉取」；解除关联后继续使用本地数据。

### 其他

- 「记录新需求」展开更多设置后，标题与验收条件各占据一整行：标题保持单行输入，验收条件为多行输入。
